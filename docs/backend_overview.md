# Backend Overview

Generated by the coding agent to describe the first backend scaffold.

## Why This Exists

The repository originally contained only a frontend prototype and architecture notes. This backend scaffold creates a stable place to add:

- real persistence
- document ingestion
- AI orchestration
- Temporal workflows
- authentication and policy controls

without forcing those concerns directly into the frontend.

## Structure

- `backend/pyproject.toml`: Python project metadata for `uv`
- `backend/.env.example`: local environment defaults
- `backend/src/hargus_api/main.py`: FastAPI application entrypoint
- `backend/src/hargus_api/config.py`: settings and environment wiring
- `backend/src/hargus_api/api/routes/`: HTTP routes
- `backend/src/hargus_api/repositories/mock_data.py`: temporary in-memory fixture data
- `backend/src/hargus_api/services/`: domain and task orchestration services
- `backend/src/hargus_api/temporal/`: Temporal client, workflow, and activity stubs
- `backend/src/hargus_api/worker.py`: worker process entrypoint
- `backend/tests/`: initial API tests

## Endpoint Strategy

Read endpoints are mock-backed for now so the frontend can move over safely before the database exists.

AI endpoints are workflow-backed by design:

- the request is accepted by the API
- an `AiTaskRecord` is created immediately
- when Temporal is enabled, a placeholder workflow is started
- the workflow currently runs a no-op stub activity

This keeps the contract stable while you plug in your own Temporal flows later.

## Temporal Contract

The current stub workflow is `AiTaskWorkflow`.

It is meant to be replaced or expanded with:

- candidate ingestion
- document parsing
- GraphRAG extraction
- background check orchestration
- candidate comparison
- final answer synthesis
