# API Overview

Generated by the coding agent so humans and LLMs can quickly understand the first backend contract.

## Base URL

- Local backend: `http://localhost:8000`
- API prefix: `/api/v1`

## Health

### `GET /api/v1/health`

Returns service metadata and whether Temporal launching is enabled.

## Vacancies

### `GET /api/v1/vacancies`

Returns all known vacancies with lightweight pagination metadata.

### `GET /api/v1/vacancies/{vacancy_id}`

Returns one vacancy or `404`.

### `GET /api/v1/vacancies/{vacancy_id}/candidates`

Returns candidates already associated with the vacancy.

## Candidates

### `GET /api/v1/candidates`

Returns all candidates.

Optional query params:

- `vacancyId`: filter candidates by vacancy

### `GET /api/v1/candidates/{candidate_id}`

Returns one candidate or `404`.

### `GET /api/v1/candidates/{candidate_id}/messages`

Returns AI chat history or recruiter message history associated with the candidate.

## AI Tasks

### `POST /api/v1/ai/tasks`

Creates an AI task record. This endpoint is intentionally asynchronous and Temporal-oriented.

Example body:

```json
{
  "type": "candidate_summary",
  "candidateId": "c1",
  "prompt": "Summarize this candidate for the backend role."
}
```

Supported `type` values:

- `candidate_summary`
- `candidate_comparison`
- `candidate_red_flags`
- `candidate_background_check`

Behavior:

- always creates a task record immediately
- stores a stub result in local memory
- if `HARGUS_TEMPORAL_ENABLED=true`, also starts the placeholder Temporal workflow

### `GET /api/v1/ai/tasks`

Returns the in-memory list of known AI tasks.

### `GET /api/v1/ai/tasks/{task_id}`

Returns one AI task or `404`.

## Migration Path

The clean migration path is:

1. Keep these response shapes stable.
2. Replace `mock_data.py` with repositories backed by Postgres and object storage.
3. Replace the stub Temporal activity with your real flow implementation.
4. Move frontend pages from mock fixtures to these endpoints one page at a time.
